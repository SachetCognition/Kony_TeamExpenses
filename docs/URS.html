2. Purpose & Scope

The Team Expense Tracker is a web application that enables a team administrator to:

  • Log shared team expenses (meals, travel, supplies, entertainment, etc.).
  • Split each expense equally among a selected subset of team members.
  • Track which team members owe money and how much.
  • Settle individual debts one expense at a time.
  • Manage categories and employee records.

Currency: Indian Rupee (₹). All monetary values are displayed with the ₹ prefix.

This specification was reverse-engineered from the Kony Visualizer project located at SachetCognition/Kony_TeamExpenses. Every requirement references the exact source file and line numbers from the original codebase to ensure traceability.

4. Functional Requirements

FR-001 — Add Expense with Equal Split

Source: modules/Module.js lines 1–63

Description: Create a new team expense and split it equally among selected employees.

Input:

  • expenseName (string, required) — from frmAddExpenseKA.tbxExpenseName.text
  • expenditure (number, required, > 0) — parsed via parseFloat(frmAddExpenseKA.tbxAmount.text); defaults to 0 if NaN
  • categoryID (number) — from dropdown frmAddExpenseKA.lbxSelectCategory.selectedKey, parsed with parseInt()
  • listOfEmployees (string[]) — from multi-select frmAddExpenseKA.cbxEmpList.selectedKeys
  • comment (string, optional) — from frmAddExpenseKA.tbxDescriptionNew.text
  • date (date) — from date picker frmAddExpenseKA.calDateOfPurchanse.dateComponents, formatted to ISO 8601

Validation:

  • If expenditure === 0 OR expenseName === '', show alert: “Please enter the mandatory feilds: expense name and amount” (line 9–11)

Business Rules:

  1. Create one Expense record with: name, expenditure, categoryID, CreatedDateTime (line 16–20)
  2. On successful expense creation, calculate: individualShare = expenditure / numberOfEmployees (line 26)
  3. For each selected employee, create an EmployeeExpense record with: employeeID, expenseID (from created expense), employeeShare = individualShare, comment, status = false (lines 48–54)
  4. On any employee_expense creation failure, set count = -1 and abort remaining creates (lines 40–46)
  5. On success of all creates, navigate to Dashboard and refresh data (lines 31–37)

Output: New expense record + N employee_expense records. Dashboard refreshed.

FR-002 — Settle Up

Source: modules/Module.js lines 66–87

Description: Mark a single employee’s share of a specific expense as settled (paid).

Input:

  • employeeID (string) — from frmSettleupKA.lblID.text
  • expenseID (number) — from frmSettleupKA.lbxSelectExpense.selectedKey, parsed with parseInt()

Business Rules:

  1. Build composite primary key: {"employeeID": employeeID, "expenseID": expenseID} (line 74)
  2. Update employee_expense.status = true using the composite key (lines 70–77)
  3. Regardless of success or failure, call populateDataInDashboardForm() to refresh the dashboard (lines 81, 85)

Output: Employee expense record status set to true. Dashboard refreshed.

FR-003 — Update Expense with Re-split

Source: modules/Module.js lines 450–595

Description: Update an existing expense’s amount and re-split among a potentially changed set of employees.

Input:

  • expenseName (string) — from frmUpdateExpenseKA.tbxExpenseName.text
  • expenditure (number) — parsed via parseInt() after stripping “₹” prefix (line 452)
  • categoryID (number) — from dropdown selected key
  • listOfEmployees (string[]) — from multi-select checkbox keys
  • comment (string, optional)
  • date (date) — from date picker

Validation:

  • Same as FR-001: reject if expenditure === 0 or expenseName === '' (line 458)

Business Rules:

  1. Look up expense by name + categoryID to retrieve expenseId (lines 467–472, 583–593)
  2. Recalculate: individualShare = amount / listOfEmployees.length (line 480)
  3. Fetch existing employee_expense records for this expense (lines 484–490)
  4. For each employee in the new list:
    • If an existing record exists → update the employeeShare (lines 507–514)
    • If new (not in existing records) → create a new employee_expense record with status=false (lines 516–526)
  5. After all employee_expense updates complete, update expense.expenditure (lines 529–537)
BUG in Original Code: The original Kony code does NOT delete employee_expense records for employees who were removed from the split. It only updates existing records and creates new ones. The new application MUST fix this by deleting employee_expense records for employees no longer in the updated split list.

Output: Updated expense record + re-calculated employee_expense records. Removed employees’ records deleted.

FR-004 — Delete Expense (Cascade)

Source: modules/Module.js lines 379–446

Description: Delete an expense and all associated employee_expense records.

Input:

  • expenseName, expenditure, categoryID, listOfEmployees — all from the Update Expense form

Business Rules:

  1. Look up expense by name + expenditure + categoryID to retrieve expenseID (lines 393–400, 434–444)
  2. Delete all employee_expense records for that expense first, iterating through each employee (lines 402–410)
  3. Once all employee_expense deletions succeed (tracked via counter), delete the expense record itself (lines 413–418)
  4. New app simplification: Use ON DELETE CASCADE on the foreign key so deleting the expense automatically removes all employee_expense records.

Output: Expense and all associated employee_expense records deleted. Dashboard navigated to.

FR-006 — Dashboard — Total Amount Spent

Source: modules/Module.js lines 104–114 (calculateAndPopulateTotalMoneyOwed)

Description: Calculate and display the total of all expenses.

Business Rules:

  1. Iterate over all expense records (from the joined category-expense objects)
  2. For each record, strip the “₹” prefix from the expenditure string: expenditure.substring(1, expenditure.length) (line 108)
  3. Parse as float and sum: totalMoneyOwed += parseFloat(expenditure) (line 109)
  4. Handle null/undefined values gracefully (line 108: kony.sdk.isNullOrUndefined check)
  5. Display result as: "Amount Spent: ₹" + totalMoneyOwed in frmDashboardKA.lblDetails (line 112)

Output: Label showing “Amount Spent: ₹X” on the dashboard.

FR-008 — Per-Category Expense Totals

Source: modules/Expense.js lines 134–183 (getTotalExpenseForEachCategory)

Description: Calculate total expenditure grouped by category.

Business Rules:

  1. Fetch all category records, then all expense records (lines 174–183)
  2. For each category, iterate over all expenses and sum expenditure where categoryRecord.id === expenseRecord.categoryID (lines 147–155)
  3. Build output array: [{categoryName, totalExpense}] for each category (lines 157–159)
  4. Categories with no matching expenses will have totalExpense = 0

Output: Array of category names with their total expense amounts.

7. Non-Functional Requirements

IDRequirementDetails
NFR-001 Currency Display All monetary values must be displayed with the Indian Rupee symbol (₹) as a prefix. The original code uses parseInt() in some places (line 151 of EmployeeExpense.js) and parseFloat() in others (line 109 of Module.js). The new application must standardize to 2 decimal places for consistency (e.g., “₹1000.00”).
NFR-002 Date Format All dates must be displayed in ISO 8601 format, truncated to date only: YYYY-MM-DD. Source: Expense.js line 99 uses toISOString().substring(0, 10).
NFR-003 Self-Contained Application The application must be fully self-contained with no external authentication service required. The original Kony app uses Kony SDK for offline objects and sync; the new app replaces this with direct PostgreSQL access via REST API.
NFR-004 Database PostgreSQL 15 as the sole persistent data store, accessed via Prisma ORM. Must support all CRUD operations, cascading deletes (ON DELETE CASCADE for employee_expense → expense), and efficient aggregation queries.
NFR-005 Technology Stack Frontend: React 18 + TypeScript + Vite + React Router v6 + TanStack Query v5. Styling: Tailwind CSS + shadcn/ui. Backend: Node.js + Express + TypeScript. ORM: Prisma. Testing: Vitest + Playwright + Supertest.
NFR-006 Responsive Design The application should be usable on desktop browsers. The original Kony app targets desktop form factor (forms/desktop/).
NFR-007 Data Integrity All expense creation and update operations involving multiple records (expense + employee_expense) must be wrapped in database transactions to ensure atomicity.
